# Auditoría de Seguridad — MorEnvíos (Semana 7)

Este documento registra el modelado de amenazas y los hallazgos de seguridad identificados en el sistema MiniCommerce y la API de almacén, evaluados contra el estándar OWASP Top 10:2025.

## 1. Tabla de Hallazgos

| ID | Categoría OWASP | Descripción de la vulnerabilidad | Evidencia / Reproducción | Impacto | Recomendación / Mitigación | Estado |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| SEC-01 | A01:2025 - Control de Acceso Roto | Las rutas de la API (ej. `POST /tienda/checkout` o `GET /movimientos`) no requieren autenticación. Cualquiera con acceso a la URL puede consultar o modificar datos. | Abrir Swagger (`/docs`) y ejecutar una compra sin ningún tipo de token o login. | Un atacante podría vaciar el inventario o consultar todo el historial de movimientos. | Implementar autenticación con JWT (JSON Web Tokens) o al menos una API Key para las rutas de escritura. | Pendiente |
| SEC-02 | A05:2025 - Mala Configuración de Seguridad | El middleware CORS está configurado con `allow_origins=["*"]`. | Revisar el código en `api/almacen.py`. | Cualquier sitio web malicioso podría hacer peticiones a nuestra API en nombre del usuario. | Restringir CORS únicamente al dominio del frontend (ej. `http://127.0.0.1:5500`). | Pendiente |
| SEC-03 | A03:2025 - Inyección | ¿Están las consultas SQL protegidas contra inyección? Revisar si se usan parámetros (`?`) o f-strings en las consultas. | Revisar el código de `almacen.py`. | Si se concatenan strings, un atacante podría borrar la base de datos. | Asegurar que TODAS las consultas usen parametrización (ej. `execute("SELECT * FROM productos WHERE id = ?", (id,))`). | Pendiente |
| SEC-04 | A03:2025 - Inyección / Validación | La ruta `POST /tienda/checkout` acepta cantidades negativas (`-50`), lo que resulta en un aumento de stock en lugar de una disminución. | Enviar un JSON con `{"producto_id": 1, "cantidad": -50}` a la API. | Un atacante podría inflar el inventario o evadir pagos. | Agregar la validación `Field(gt=0)` al modelo `ItemCarrito` y límites máximos. | En proceso |
| SEC-05 | A03:2025 - Inyección (XSS) | El frontend usa `innerHTML` para renderizar el nombre y código del producto. Un nombre malicioso con etiquetas `<script>` permitiría ejecutar código en el navegador del usuario (XSS almacenado). | Modificar el nombre de un producto en la BD por `<script>alert('hackeado')</script>`. | Robo de sesiones o redirecciones maliciosas. | Usar `createElement` y `textContent` en el JS (ya corregido por Maira). Validar longitud y caracteres en el backend. | Resuelto (Frontend) |

Validar longitud y caracteres en el backend. | Resuelto (Frontend) |
| SEC-06 | A06:2025 - Componentes Vulnerables | El proyecto utilizaba versiones desactualizadas de `pip`, `setuptools`, `certifi` y `opentelemetry-api` con vulnerabilidades conocidas (CVEs). | Ejecutar `pip-audit` en la terminal. | Posible ejecución de código malicioso o fallos en la validación de certificados SSL. | Actualizar a las últimas versiones con `pip install --upgrade` y regenerar el `requirements.txt`. | Resuelto |
| SEC-07 | A05:2025 - Mala Configuración | La documentación interactiva (`/docs` y `/redoc`) está expuesta por defecto en todos los entornos. | Abrir `http://127.0.0.1:8000/docs` en el navegador. | Un atacante puede mapear todas las rutas y modelos de datos fácilmente. | Ocultar `docs_url` y `redoc_url` si la variable de entorno no es "desarrollo". | Resuelto |
